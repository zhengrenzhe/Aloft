# Aloft v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a native macOS menu bar application that persists grouped command definitions, manages each command through a POSIX PTY and process group, reports kernel-backed liveness, displays cleaned live output, and surfaces keyword matches.

**Architecture:** A SwiftUI accessory application owns durable configuration and runtime stores. A focused C target performs the async-signal-safe `openpty`/`fork`/`setsid`/`TIOCSCTTY`/`exec` launch path, while Swift actors supervise process groups and stream PTY bytes through a plain-text output pipeline. AppKit bridges provide the directory picker and performant read-only output view; Ghostty remains an optional, separate companion shell.

**Tech Stack:** Swift 6, SwiftUI, Observation, AppKit, SwiftPM, XCTest, Darwin POSIX APIs, a small C interoperability target, JSON persistence.

## Global Constraints

- Deployment target is macOS 14 or newer.
- The v1 app is menu-bar-only with `LSUIElement = true` and no Dock icon.
- v1 has no third-party runtime dependency and does not link `libghostty`.
- Aloft owns every managed PTY and process group.
- Process liveness comes from `waitpid(..., WNOHANG)` and `killpg(pgid, 0)`.
- Stop sends `SIGTERM`, waits exactly five seconds in production, and never sends `SIGKILL`.
- Commands execute as `/bin/zsh -l -c <command>` in the configured cwd.
- Output remains in memory, capped at 20,000 committed lines per entry.
- Keywords are nonempty, case-sensitive literal substrings.
- Ghostty integration creates a separate interactive shell and never attaches to a managed process.
- All production behavior follows red-green-refactor; every completion claim requires fresh `swift test`, `swift build`, and bundled-app verification evidence.

```swift
// Sources/AloftApp/Persistence/ConfigurationRepository.swift
import Foundation

struct ConfigurationRepository: Sendable {
    let fileURL: URL

    func load() throws -> WorkspaceConfiguration {
        guard FileManager.default.fileExists(atPath: fileURL.path) else {
            return .empty
        }
        return try JSONDecoder().decode(
            WorkspaceConfiguration.self,
            from: Data(contentsOf: fileURL)
        )
    }

    func save(_ configuration: WorkspaceConfiguration) throws {
        let directory = fileURL.deletingLastPathComponent()
        try FileManager.default.createDirectory(
            at: directory,
            withIntermediateDirectories: true
        )
        let encoder = JSONEncoder()
        encoder.outputFormatting = [.prettyPrinted, .sortedKeys]
        try encoder.encode(configuration).write(to: fileURL, options: .atomic)
    }
}
```

- [ ] **Step 4: Implement the child-safe launch path**

Implement `aloft_launch` with this exact ownership:

```c
int master_fd = -1;
int slave_fd = -1;
int error_pipe[2] = {-1, -1};

if (openpty(&master_fd, &slave_fd, NULL, NULL, NULL) == -1) {
    return failure(ALOFT_LAUNCH_OPEN_PTY, errno);
}
if (pipe(error_pipe) == -1) {
    close(master_fd);
    close(slave_fd);
    return failure(ALOFT_LAUNCH_ERROR_PIPE, errno);
}
fcntl(error_pipe[1], F_SETFD, FD_CLOEXEC);
pid_t pid = fork();
```

The child closes the read side, then executes:

```c
if (setsid() == -1) child_fail(error_pipe[1], ALOFT_LAUNCH_SETSID);
if (ioctl(slave_fd, TIOCSCTTY, 0) == -1) {
    child_fail(error_pipe[1], ALOFT_LAUNCH_CONTROLLING_TTY);
}
if (dup2(slave_fd, STDIN_FILENO) == -1 ||
    dup2(slave_fd, STDOUT_FILENO) == -1 ||
    dup2(slave_fd, STDERR_FILENO) == -1) {
    child_fail(error_pipe[1], ALOFT_LAUNCH_DUP_STDIO);
}
close(master_fd);
close(slave_fd);
if (chdir(cwd) == -1) child_fail(error_pipe[1], ALOFT_LAUNCH_CHDIR);
execl("/bin/zsh", "zsh", "-l", "-c", command, (char *)NULL);
child_fail(error_pipe[1], ALOFT_LAUNCH_EXEC);
```

`child_fail` writes `{phase, errno}` with one `write`, then calls `_exit(127)`.
The parent closes the slave and error-pipe write end, reads the error record,
and treats EOF as successful `exec` because the write end is close-on-exec.
Successful return sets the PTY master to `O_NONBLOCK` and returns
`pid == pgid`.

Implement probes with:

```c
int aloft_process_group_exists(pid_t pgid) {
    if (killpg(pgid, 0) == 0 || errno == EPERM) return 1;
    if (errno == ESRCH) return 0;
    return -errno;
}
```

`aloft_signal_process_group` returns `0` or `-errno`; `aloft_waitpid` forwards
to `waitpid`.

- [ ] **Step 3: Implement streaming UTF-8 and ANSI state machines**

`UTF8StreamDecoder` stores at most three trailing bytes. It finds the final
UTF-8 leading byte, retains an incomplete scalar, and decodes the complete
prefix with replacement for malformed input.

`ANSITextFilter` uses:

```swift
enum State {
    case text
    case escape
    case csi
    case osc
    case oscEscape
}
```

Rules:

- text `ESC` enters `.escape`;
- escape `[` enters `.csi`;
- escape `]` enters `.osc`;
- CSI ends on a scalar in `0x40...0x7E`;
- OSC ends on BEL;
- OSC `ESC` enters `.oscEscape`;
- OSC escape `\` returns to text;
- unsupported single-character escapes consume one scalar and return to text.

```swift
actor ProcessSupervisor {
    typealias OutputHandler = @Sendable (Data) -> Void

    func start(
        entry: CommandEntry,
        onOutput: @escaping OutputHandler
    ) throws -> ProcessSnapshot

    func refresh(entryID: UUID) throws -> ProcessSnapshot

    func stop(

        timeout: Duration = .seconds(5)

        timeout: Duration = .seconds(5)

}
```

Exact behavior:

- timeout returns `.timedOut` without closing the PTY or deleting the record;
- `restart` throws `ProcessSupervisorError.stopTimedOut` instead of launching

- [ ] **Step 1: Write the project-local build and bundle script**

The script accepts `run`, `--debug`, `--logs`, `--telemetry`, and `--verify`.
Before building, it asks a previous Aloft instance to quit through:

```bash
/usr/bin/osascript -e 'tell application id "com.bytedance.aloft" to quit'
```

It then polls `pgrep -x Aloft` for six seconds. If safe quit was cancelled
because a managed process resisted `SIGTERM`, the script exits nonzero and
does not launch a second instance. After the prior process exits, it runs
`swift build` and stages:

```text
dist/Aloft.app/
└── Contents/
    ├── Info.plist
    └── MacOS/Aloft
```

Generate an `Info.plist` containing:

```xml
<key>CFBundleExecutable</key><string>Aloft</string>
<key>CFBundleIdentifier</key><string>com.bytedance.aloft</string>
<key>CFBundleName</key><string>Aloft</string>
<key>CFBundlePackageType</key><string>APPL</string>
<key>LSMinimumSystemVersion</key><string>14.0</string>
<key>LSUIElement</key><true/>
<key>NSAppleEventsUsageDescription</key>
<string>Aloft opens optional companion shells in Ghostty.</string>
<key>NSPrincipalClass</key><string>NSApplication</string>
```

Launch with:

```bash
/usr/bin/open -n "$project_root/dist/Aloft.app"
```

Mode behavior matches the canonical macOS run workflow:

- `run`: launch the app bundle;
- `--debug`: launch `Contents/MacOS/Aloft` under `lldb`;
- `--logs`: launch the bundle and stream unified logs for process `Aloft`;
- `--telemetry`: launch the bundle and stream unified logs for subsystem
  `com.bytedance.aloft`;
- `--verify`: launch the bundle, poll `pgrep -x Aloft` for up to five seconds,
  and exit nonzero when the process never appears.
